# 回声编辑台

面向 SillyTavern 1.18.0 聊天补全预设的轻量第三方扩展，优先照顾手机上的编辑体验。

短条目在目录内直接修改，长正文展开全屏写作。新草稿先在指定位置出现，首次保存同时写入内容与预设排列，省去到下拉列表中寻找条目、再手动链接的步骤。

插件没有后端、构建步骤或外部依赖，不修改酒馆核心文件。

## 安装

在酒馆的扩展面板中选择 **安装扩展**，输入仓库地址：

```text
https://github.com/Titania-elf/echo-editor
```

安装完成后刷新酒馆。进入 **AI 响应配置 → 聊天补全预设**，点击 **回声编辑台**。

也可以下载仓库文件，将插件目录放到 `public/scripts/extensions/third-party/回声编辑台` 后刷新。设置面板会按实际安装目录加载，支持酒馆安装器使用的 `echo-editor` 目录名。

已有本地版本时，先保存正在编辑的内容，将旧版插件目录移出第三方扩展目录，再安装仓库版本，避免同时加载两份插件。旧版设置会自动读取。

## 使用

1. 安装完成后刷新酒馆。
2. 打开 AI 响应配置，在原生预设区域点击 **回声编辑台**。也可以从扩展设置进入。入口的图标和文字保持单行，空间不足时整颗按钮换行。
3. 默认接管原生新增和铅笔编辑按钮；在扩展设置中可关闭接管，继续使用原生编辑器。桌面端 Shift 点击原生按钮可临时绕过接管。
4. 点击条目在目录内展开；长正文点击 **全屏**。保存不会关闭编辑区。收起和切换条目保留当前草稿与文本选区。
5. 条目右侧菜单提供 **在上方新增 / 在下方新增**。草稿立即占据位置，第一次保存同时写入内容和原生排列，无需手动链接。
6. **整理模式中按住把手拖动排序**。没有上下移动按钮。松手后保存正式条目的排列；纯草稿的位置仅保留在当前页面。拖近列表边缘可自动滚动，取消触摸会撤销这次拖动。
7. **添加已有** 是可搜索的原生条目库；新添加条目默认关闭。**从排列移除** 不等于彻底删除。
8. 右上角的主题按钮提供 **纸白 / 夜色 / 跟随酒馆**，扩展设置中也可选择。首次默认纸白，后续记住选择。切换主题保留草稿、光标和编辑位置，不影响酒馆全局主题。
9. **预设** 返回按钮会回到酒馆的 AI 响应配置面板，保留当前预设。恢复原有滚动位置，并让刚编辑的正式条目保持可见；如果正在编写新草稿，则定位到附近的正式条目。

## 配色

- **纸白**：米白纸面、稍亮的正文输入区、深墨文字和灰蓝强调色。
- **夜色**：石墨灰纸面、柔和灰白文字和浅灰蓝强调色。
- **跟随酒馆**：继承酒馆当前的文字、背景、边框与强调色，保留原有主题效果。
- 主题选择通过同一个后台保存队列写入插件偏好，失败时保留当前选择并提供重试。
- 纸白与夜色中的输入框使用插件自己的背景、文字、边框和提示文字，覆盖酒馆主题的全局强制规则。该覆盖只限回声编辑台的两套独立主题。

## 保存边界

- **保存条目、开关、添加/移除与排序**：界面立即应用改动，后台调用原生设置保存，不锁住页面，也不显示阻塞式加载；不覆盖命名预设文件。
- 后台写入串行执行。第一笔立即发起，连续操作合并到后续最新一笔，避免较旧请求覆盖新状态。收到确认前保留待保存标记；失败时提示并显示“重试保存”。
- **更新预设**：明确确认后等待后台设置写入，再覆盖当前命名预设（包括当前参数、已保存条目和排列），同步原生缓存，不重新套用预设。只有这个跨步骤的操作会临时锁定编辑，防止切换期间写错预设。
- 新草稿默认不参与发送。第一次保存时可勾选启用，或在扩展设置改变这个默认选项。
- 草稿在本次页面中保留，关闭回声编辑台再打开仍可继续；**不保证刷新、关闭标签页或手机回收页面后恢复**，请及时保存。
- 原生下拉框切换预设前会提示保存或放弃。其他插件通过程序切换预设时仍保留未保存草稿在页面内，并阻止旧上下文的操作写入新预设。
- 设置保存或预设更新没有得到确认时会提示失败，不显示成功；可重试。

## 兼容与限制

- 使用原生 `prompts` / `prompt_order` 格式和唯一标识，只修改实际编辑过的字段。保留未知字段、开关和内置条目限制。
- 界面使用独立命名空间，提供两套插件配色及跟随酒馆模式；不替换整个 Prompt Manager，不拦截全局 fetch，也不参与生成提示词。
- 插件目录名和新设置键使用 `回声编辑台`。首次加载会自动读取旧版 `st-preset-mobile-editor` 的设置，保留主题、接管选项和新条目启用偏好；酒馆扩展列表中的旧禁用状态也会迁移。
- 内部管理器接口的依赖集中在 `adapter.js`。酒馆升级后需要复核。
- 与其他预设插件共用底层数据；如其他编辑器同时修改同一字段，会保留草稿并提示冲突。其他插件的所有功能组合未全面验证。
- “聊天内注入”的实际顺序受深度与注入顺序影响，不只取决于目录排列。

## 开发与验证

```sh
npm test
```

无需安装依赖。已有 14 项单元测试覆盖字段合并、冲突、只读来源、原生排列完整性、草稿锚点和后台写入队列。

开发过程中在 390px 手机视口验证过新增、保存并加入、拖动、全屏选区、预设更新和切换保护；验证时拦截设置和预设保存请求，避免写入真实用户文件。

三种主题、入口布局、返回定位和输入框主题覆盖已完成静态检查，当前发布版本尚未完成全面的手机浏览器实机回归。
