# 回声编辑台

面向 SillyTavern 1.18.0 聊天补全预设的轻量第三方扩展，优先照顾手机上的编辑体验。

短条目在目录内直接修改，长正文展开全屏写作。新草稿先在指定位置出现，首次保存同时写入内容与预设排列，省去到下拉列表中寻找条目、再手动链接的步骤。

插件没有后端、构建步骤或外部依赖，不修改酒馆核心文件。

## 安装

在酒馆的扩展面板中选择 **安装扩展**，输入仓库地址：

```text
https://github.com/Titania-elf/echo-editor
```

安装完成后刷新酒馆。进入 **AI 响应配置 → 聊天补全预设**，点击 **回声编辑台**。

也可以下载仓库文件，将插件目录放到 `public/scripts/extensions/third-party/回声编辑台` 后刷新。设置面板会按实际安装目录加载，支持酒馆安装器使用的 `echo-editor` 目录名。

已有本地版本时，先保存正在编辑的内容，将旧版插件目录移出第三方扩展目录，再安装仓库版本，避免同时加载两份插件。旧版设置会自动读取。

## 使用

1. 安装完成后刷新酒馆。
2. 打开 AI 响应配置，在原生预设区域点击 **回声编辑台**。也可以从扩展设置进入。入口的图标和文字保持单行，空间不足时整颗按钮换行。
3. 原生小铅笔始终打开酒馆自己的编辑器，不再跳转回声编辑台，也不走回声编辑台的历史版本保存流程。原生 **新增** 按钮默认由回声编辑台接管，可在扩展设置中关闭；桌面端 Shift 点击原生新增按钮可临时绕过接管。需要回声编辑台的正文全屏、分组或历史功能时，从独立的 **回声编辑台** 入口进入。
4. 点击条目在目录内展开；长正文点击 **全屏**，只展开正文文本框，隐藏标题输入、消息角色、高级设置和条目管理操作。顶部保留退出、主题、字数与保存状态、保存按钮；正文占满其余屏幕，宽屏限制行长以便阅读。点击 **退出全屏** 或按 Esc 回到原条目，保留草稿、文本选区和正文滚动；通常恢复原搜索与目录位置。如果修改后的正文已不匹配搜索，手机端会清空搜索并定位到当前条目，避免返回后找不到正文。退出不自动保存。顶部保存或 Ctrl / ⌘ + S 仍使用原来的条目保存逻辑，保存后可继续全屏编辑。
5. 条目右侧菜单提供 **在上方新增 / 在下方新增**。草稿立即占据位置，第一次保存同时写入内容和原生排列，无需手动链接。
6. **整理模式中按住把手拖动排序**。没有上下移动按钮。松手后保存正式条目的排列；纯草稿的位置仅保留在当前页面。拖近列表边缘可自动滚动，取消触摸会撤销这次拖动。
7. **添加已有** 是可搜索的原生条目库；新添加条目默认关闭。**从排列移除** 不等于彻底删除。条目更多菜单中的 **彻底删除条目** 需要再次确认，会从当前配置的条目库删除该条目并清除各角色排列中的引用；内置受限条目不可删除。删除本条未保存修改时会明确提示，其他条目草稿保留。删除后仍需 **更新预设** 才会写入当前命名预设文件；其他命名预设文件不自动改动。删除分组边界会取消相关分组，但不删除其余成员。未保存的新草稿继续使用 **放弃草稿**。
8. 右上角的主题按钮提供 **纸白 / 夜色 / 跟随酒馆**，扩展设置中也可选择。首次默认纸白，后续记住选择。切换主题保留草稿、光标和编辑位置，不影响酒馆全局主题。
9. **预设** 返回按钮会回到酒馆的 AI 响应配置面板，保留当前预设。恢复原有滚动位置，并让刚编辑的正式条目保持可见；如果正在编写新草稿，则定位到附近的正式条目。

## 电脑端布局

- 默认 **自动**：可用窗口宽度达到 1024px 时显示左侧目录、右侧编辑器；窄窗口保持原来的手机单栏样式及操作流程。
- 在顶部 **双栏 / 单栏** 按钮或扩展设置的 **界面布局** 中选择自动、手机单栏或电脑双栏。选择电脑双栏后，窄窗口仍会临时退回单栏，重新加宽时自动恢复。
- 目录与正文独立滚动，右侧保存栏保持可见。点击目录条目切换右侧内容；再次点击当前条目不会收起电脑编辑器。
- 双栏不提供独立的“新增条目”按钮。新增通过条目菜单的 **在上方新增 / 在下方新增** 完成，不因电脑布局重新增加入口。
- 搜索过滤、分组折叠或整理排列不隐藏当前电脑编辑器。草稿、文本选区及正文滚动位置继续按条目保留，不自动保存。
- 拖动分隔线调整目录宽度；聚焦分隔线后可用左右方向键微调，Home / End 选择最窄 / 最宽，双击恢复默认宽度。宽度记入插件偏好，不影响手机样式。
- 电脑和手机均使用正文专注全屏，只有同一个正文文本框进入全屏，其他编辑字段留在原界面。退出后恢复原布局与编辑位置；电脑端始终保留搜索，手机端仅在正文不再匹配时清空搜索，以便显示当前条目。只读正文和酒馆内容占位符不提供全屏编辑入口。
- 电脑端条目菜单靠近按钮弹出，条目库、分组管理与确认操作使用居中面板；手机端继续使用底部操作面板。
- 布局与纸白、夜色、跟随酒馆三种主题独立。两种布局复用同一个编辑器和相同的原生保存逻辑。

## 配色

- **纸白**：米白纸面、稍亮的正文输入区、深墨文字和灰蓝强调色。
- **夜色**：石墨灰纸面、柔和灰白文字和浅灰蓝强调色。
- **跟随酒馆**：继承酒馆当前的文字、背景、边框与强调色，保留原有主题效果。
- 主题选择通过同一个后台保存队列写入插件偏好，失败时保留当前选择并提供重试。
- 纸白与夜色中的输入框使用插件自己的背景、文字、边框和提示文字，覆盖酒馆主题的全局强制规则。该覆盖只限回声编辑台的两套独立主题。

## 保存边界

- **保存条目、开关、添加/移除、删除与排序**：界面立即应用改动，后台调用原生设置保存，不锁住页面，也不显示阻塞式加载；不覆盖命名预设文件。
- 后台写入串行执行。第一笔立即发起，连续操作合并到后续最新一笔，避免较旧请求覆盖新状态。收到确认前保留待保存标记；失败时提示并显示“重试保存”。
- **更新预设**：填写版本号与更新说明，明确确认后等待后台设置写入，再更新当前命名预设（包括当前参数、已保存条目和排列），同步原生缓存，并持久保存该次完整版本；不重新套用预设。完整版本保存、历史载入等跨步骤操作会临时锁定编辑，防止切换期间写错预设。
- 新草稿默认不参与发送。第一次保存时可勾选启用，或在扩展设置改变这个默认选项。
- 草稿在本次页面中保留，关闭回声编辑台再打开仍可继续；**不保证刷新、关闭标签页或手机回收页面后恢复**，请及时保存。
- 原生下拉框切换预设前会提示保存或放弃。其他插件通过程序切换预设时仍保留未保存草稿在页面内，并阻止旧上下文的操作写入新预设。
- 设置保存或预设更新没有得到确认时会提示失败，不显示成功；可重试。

## 正文批量替换

- 搜索到正文时，搜索区域显示 **批量替换**；平时隐藏。开启 **仅标题** 时禁用正文替换；仅标题或分组名命中的条目不参与替换。
- 查找内容来自当前搜索，沿用普通文本、去掉查找词前后空白和默认忽略大小写的规则；可勾选 **区分大小写**。不支持正则表达式。替换文本支持多行并严格原样写入，`$1`、`$&` 和反斜杠不会展开。
- 预览包含每个可修改条目的标题、全部命中次数和替换前后片段，可逐条勾选或全选。每条最多展示前三处片段，确认后会替换所选正文中的全部非重叠命中，而非只替换第一处。
- 包含当前目录里的已关闭条目、已有未保存修改及新草稿。正文只读或内容占位符会跳过并说明原因；未加入目录的条目库、其他预设和历史版本不参与替换。
- 替换内容留空表示删除匹配正文，必须另外勾选删除确认。替换后正文不变的条目跳过，不制造无意义的修改标记。
- **确认替换只改本页草稿正文，不自动保存条目、更新命名预设或创建历史版本**。标题、角色、高级属性、排列和启用状态保持不变；替换前已有的其他修改继续保留。可逐条保存，或在 **更新预设** 中选择 **保存修改并更新预设** 统一提交为新版本。
- 替换后仍保留结果清单，可从 **查看替换结果** 找回不再命中原搜索的条目，或 **清空搜索查看修改**。
- 支持 **撤销本次替换**，恢复本次替换前的正文，包括原来已有的未保存草稿。只保留最近一次批量替换的撤销记录；正文已继续编辑、保存、移除或预设重新载入时，拒绝一键撤销，避免覆盖后续改动。
- 预览期间正文、条目、权限或搜索上下文变化时，整批停止；可重新读取正文再确认，不会先改一部分条目。批量替换仍属于本页草稿，刷新或关闭标签页前请保存。

## 预设历史版本

- 顶部 **更新预设** 的确认窗口可填写版本号和更新说明。默认从 `v1.0` 开始递增，支持手动填写；同一预设内不允许重复版本号，保存不会覆盖旧历史。单独 **保存条目**、打字、开关和排序不产生完整版本。
- 首次完整保存会先将酒馆已载入的原命名预设登记为 **初始版本**，确认初始历史保存成功后才覆盖命名文件。初始版本的时间是首次登记时间，配套分组取打开编辑台时的记录；无法追溯启用该功能前已被覆盖的版本。
- 每版是独立的完整快照，包含全部条目库（包括未加入排列的条目）、所有角色的排列与开关、预设参数、扩展字段和配套分组。保留未知字段，不把版本拆成多个酒馆命名预设。
- 点击 **历史版本**，可按版本号或更新说明查找，**查看** 为只读正文预览。历史按预设名称分别管理，存入酒馆的扩展设置；保存确认后刷新、重启仍可找到，不依赖页面草稿或浏览器本地存储。
- **载入此版本** 替换并保存当前运行工作配置，但不立刻覆盖命名预设文件。连接参数遵循酒馆的“绑定连接”设置。界面显示 **基于某版编辑**，修改满意后再 **更新预设** 为新版本。
- 载入前存在未完成改动时，可选择 **保存为新版本后载入 / 放弃当前改动并载入 / 取消**。其他角色工作区的未保存草稿仅在本页保留，不会自动纳入当前版本保存。
- 从旧版重新编辑，默认版本号依然按全部已有版本递增，例如已有 `v1.0 → v1.1 → v1.2`，载入 `v1.0` 后另存为 `v1.3`。原来的后续版本仍保留，记录中可看到新版本的编辑起点。
- 删除历史记录需要确认，只删除这条历史，不改变当前配置或命名文件。不会自动清理版本；总历史超过约 5 MiB 时提示占用，避免大量全量快照使设置保存变慢。
- 命名预设已写入但历史存储失败时会明确区分并提供 **重试保存**，重试只确认历史，不再次覆盖命名文件或生成重复版本。确认载入期间发生外部修改或预设切换时会阻止继续操作。

## 兼容与限制

- 使用原生 `prompts` / `prompt_order` 格式和唯一标识，只修改实际编辑过的字段。保留未知字段、开关和内置条目限制。
- 界面使用独立命名空间，提供两套插件配色及跟随酒馆模式；不替换整个 Prompt Manager，不拦截全局 fetch，也不参与生成提示词。
- 插件目录名和新设置键使用 `回声编辑台`。首次加载会自动读取旧版 `st-preset-mobile-editor` 的设置，保留主题、接管选项和新条目启用偏好；酒馆扩展列表中的旧禁用状态也会迁移。
- 内部管理器接口的依赖集中在 `adapter.js`。酒馆升级后需要复核。
- 与其他预设插件共用底层数据；如其他编辑器同时修改同一字段，会保留草稿并提示冲突。其他插件的所有功能组合未全面验证。
- “聊天内注入”的实际顺序受深度与注入顺序影响，不只取决于目录排列。
